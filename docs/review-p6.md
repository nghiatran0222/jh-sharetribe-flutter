# P6 — adversarial review and fixes

A fresh read-only agent reviewed the repo at `2c76926` against `docs/brief.md` and every Accepted ADR, told to refute rather than confirm. This is its findings with the status of each. Verdict in its words: *"the engineering is above the bar; the submission is below it"* — the Flutter work is solid, but nothing in the repo had ever touched a real Sharetribe marketplace.

## Fixed in the P6 fix session

| # | Finding | Fix |
|--|--|--|
| 3 | **Mock mode hit the network.** 24 listing images pointed at `picsum.photos`, contradicting "mock mode must run without network" (AGENTS.md). Unit tests hid it because `flutter_test` stubs `HttpClient`. | Images are bundled assets under `flutter_app/assets/mock/`, addressed with an `asset:` scheme that `ListingTile` renders with `Image.asset`. `mock_repositories_test` now asserts the scheme, so a URL cannot creep back. |
| 4 | **The README's headline screenshot showed 24 broken images**, generated by an offline run and committed unexamined. | Regenerated after the asset fix. |
| 5 | **Endpoint paths wrong in three docs.** The code was right (`/v1/api/listings/query`, `/v1/api/current_user/show`); `AGENTS.md`, ADR 0015 and `analysis-of-requirements.md` each dropped the `/v1/api/` prefix. | All three corrected, verified against the Marketplace API reference. |
| 6 | **`live.env.json` was not gitignored** although the README called it "a gitignored file", so a reader following it could commit their Client ID. | `.gitignore` now ignores `*.env.json` (keeping `*.env.example.json`). |
| 7 | **`AGENTS.md`, the declared single source of truth, was stale** — "No Flutter code exists yet", "Layout (planned)", "once it exists". | Status, layout and commands rewritten to describe the repo as built. |
| 8 | **Mock repositories could throw**, violating ADR 0009. They call a `TokenStore`, and mock mode uses the real `SecureTokenStore`, so a `PlatformException` escaped as an uncaught throw. | Both mock repositories now run through `guard()`. |
| 10 | **The pull-to-refresh test asserted something already true before the gesture** — deleting `ListingsCubit.refresh()` still passed it. | New `test/listings_page_test.dart` drives the page with a call-counting repository: refresh must reach the repository *and* show the new data. Retry-on-error and empty state are covered the same way. |
| 12 | **`AppError` compared by `runtimeType`**, so `ServerError(503)` equalled `ServerError(500)` and no test could catch a wrong status. | `ServerError` and `UnexpectedError` compare by value; both Cubit states compare the error itself. |
| 13 | ADR 0003 claimed the app selects the alias through an `Env` default that does not exist. | ADR amended: the alias is selected in Console until the request flow is built (P4b). |
| 14 | README said "66 tests" twice (it was 67) and omitted ADR 0016 from Key decisions. | Corrected; the count is now 72. |
| 17 | Missing negative tests around refresh. | Added: a retry that also 401s does not refresh twice, and a request carrying its own token is left alone by the refresh path. |
| 20 | `MockAuthRepository._accounts` was process-global mutable state, leaking sign-ups between tests. | Now an instance field. |
| 21 | `_sameIds` compared full listings, not ids. | Renamed `_sameListings`. |

## Closed by P7 (2026-09-20)

The review's two MUST findings — the ones it said sank the submission — are closed.

| # | Finding | Evidence |
|--|--|--|
| 1 | No Sharetribe environment was ever created. | Marketplace `nghiatran-test` created, the process published with `release-1` on version 1 and `release-2` on version 2, and a provider with published listings plus a customer user seeded in Console. |
| 11 | ADR 0015 promised a real captured `listings/query` fixture. | `test/fixtures/listings_query_live.json` is a real response from the marketplace (ids, provider display name and signed image URLs replaced; field names, nesting and value types untouched), parsed by `test/live_fixture_test.dart`. All six assertions passed on the first run, so the parser needed no change. The `meta` block it captured (`totalItems: 10`, `totalPages: 2`) is also the evidence for finding 18, pagination. |
| 2 | Nothing has ever talked to Sharetribe. | A live run logged in as the customer and fetched real listings, authors, prices and images over the Marketplace API: `docs/screenshots/04-live-listings.png`. It confirms against real data what only fixtures had covered: the auth and query paths, the JSON:API mapping, the `landscape-crop` image variant, the author relationship, and prices rendered from minor units (49.99 USD). |

## Process criticism worth keeping

The review noted 16 ADRs, a 349-line plan and two agent hooks against ~3,000 lines of Dart, with ADRs 0012 and 0014 documenting the author's own AI tooling rather than the product — "process performance", in its words, while the thing the brief actually asked for (a live marketplace) had no record at all. Worth weighing before adding more process to this repo.

## What it rated as genuinely good

The single-flight refresh in the `QueuedInterceptor` with its parallel-401 test ("senior-grade and better than most candidates produce"), the JSON:API denormalizer with Sharetribe's `{uuid: …}` tolerance and null-safe image variants, `FakeAdapter` instead of a mocking package, the clean separation of the Marketplace and Integration API trust levels, and the v2 process change with its written rationale.
